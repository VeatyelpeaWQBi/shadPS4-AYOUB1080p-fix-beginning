# 着色器与管线缓存、预热

首次出现的新效果可能同时触发着色器转译、原生管线创建、资源读取和上传。
本改造保存已产生的编译成果，在下次启动时恢复并预热；不修改游戏本体。

## 缓存路径

缓存位于模拟器实际用户目录的 `cache/<游戏编号>/pipeline-v2/`。
本机默认为 `%APPDATA%/shadPS4/cache/CUSA00309/pipeline-v2/`；存在便携 user 目录时，
使用该模拟器实际选择的目录。游戏存档在 home 下，删除存档不会删除这些缓存。

后台队列保存 SPIR-V、着色器元数据和管线描述；限制队列内存、合并同名待写快照。
文件带长度与校验值，完整写入后原子替换，退出时排空已接受的任务。
旧独立文件和 ZIP 只读导入，不修改旧文件。缓存恢复核对原始变体槽位和序列化身份，
恢复完整运行时状态及辅助片元着色器；损坏、不兼容或缺失记录回退到按需编译。

Vulkan 驱动缓存校验 vendor/device、驱动版本和 UUID。后台周期性保存，避开编译
繁忙时段；正常关闭也补存最终快照。具体驱动自身的缓存调用开销取决于驱动实现。

## 预热与计算任务

启动先恢复完整着色器变体，再并行创建已知计算/图形管线；完整计算变体也可恢复
缺少管线 key 的记录。预热结束后进入游戏。外部 shader patch 启用时跳过恢复，
避免用缓存覆盖用户修改。

inFAMOUS 配置启用计算管线并行创建。录制线程在实际绑定前等待编译结果，并限制
生产者排队容量，所有计算任务保留。已有 graphics-only 异步设置继续使用。
预热仅覆盖已有记录，不能推导所有未知效果的资源、绑定和运行时状态。

## 自动预算

- 查询当前可用物理内存；显卡提供预算扩展时使用显存预算减去已用量。
- 保留 512 MiB–8 GiB 可用 RAM；额外预热预算不超过剩余可用量的 75%，上限 8 GiB。
- 保留约四分之一可用显存，范围 256 MiB–4 GiB；每次额外预热重新检查压力。
- 驱动缓存上限为预热预算四分之一，最多 1 GiB；后台写队列为 16–512 MiB。
- inFAMOUS 上传池按预算保留可复用块，最多每池 2 GiB；启动预触碰最多 256 MiB。
  压力出现时回收可以安全释放的块，不覆盖使用中的数据。

这些数值是允许的预算，不是一次性分配量。缓存磁盘增长取决于实际游戏内容；
旧格式首次导入可能产生一份新的副本。不会因为内存充足而预载整个游戏。

## 验证和诊断

用户在 1080p 游玩中确认首次卡顿明显减少，常规场景多数为 55–60 FPS；已有缓存
的重伤/死亡效果复测未再卡顿。车祸粒子场景持续约 40 FPS，不宣称本改造消除所有停顿。
提交前 Release 构建及 5 项检查通过，覆盖校验、原子替换、后台队列、关闭排空、
异常数据、预算、运行时复用、编译结果发布与缓冲区间正确性。

```powershell
.\scripts\build_release.ps1 -RunCacheTests
.\scripts\run_infamous_hk.ps1 -EmulatorPath '.\Build\x64-Clang-Release\shadps4.exe' -Resolution 1080p -Performance -CacheDiagnostic
```

脚本使用已有系统工具与依赖，不自动下载安装。构建入口见
[Windows 本机构建](windows-local-build.md)，实测范围和采样限制见
[性能诊断](infamous-performance-diagnostics.md)。缓存机制涉及通用引擎，实机验证
主要针对港版 1080p；其他游戏/区域和 PS4 Pro 4K 尚未完成同等回归。
