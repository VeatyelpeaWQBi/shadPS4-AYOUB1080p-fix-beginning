# 港版火焰周期消失：回归定位与修正（2026-10-13）

提交前说明：下文为历史对照及当时的 EXE/7 项检查记录。实验性 CPU 分组实现和
对应开关已从本次提交中移除；当前构建保留港版提前访问保护修正，检查项为 5 个。
后续最终对照与清理范围见 [最后一轮记录](infamous-particle-final-round.md)。

## 结论

用户报告正确：此前自动选核方案下的 58–60 FPS 伴随多处火焰同步消失与重播，
不能视为正确渲染条件下的性能收益。此前仅核对静态截图，遗漏了动画连续性；
该优化成功结论已撤销，源码和启动 INI 默认都设为 `gpu_core_reservation = 0`。

故障与 GPU 可写缓冲的延后内存访问保护有关。原路径在命令处理线程中先标记 GPU
所有权，却把读写保护留给上传 worker；在保护生效前，客体 CPU 访问不会触发本来
需要的 GPU 回读。代码分析推断这会使游戏读取旧的粒子反馈状态，较快的命令处理
使此窗口显著暴露。尚未抓取每次错误读取的具体地址和值，因此不声称逐条定位了
所有错误反馈。

单独提前应用保护、仍保留后台复制后，连续火焰恢复；恢复旧的延后保护后，集体
消失再次出现。修正限制在 `CUSA00309` 的 GPU 可写资源，不改变其他地区的策略。
着色器、粒子数量、分辨率、游戏文件、已有缓存与已验证的剧情选择 CPU 复用均保留。

## 连续画面对照

同一车祸存档、同一位置和镜头，在显式隔离 home 下用引擎的 game-only 截图采样。
多个画面区域的橙色像素计数用于发现同时熄灭，不把它当作粒子个数或完整画质证明。
代表性最低/最高帧已直接检查；完整序列保存在对应的 capture MKV 中。
RGB 视频使用 lossless 编码，逐帧与 PNG 的 RGB 字节核对，透明度原本全部为 255。
确认每个像素一致后，才归档冗余测试 PNG；每段保留代表性 PNG。
